# Plustek OpticBook 4800 под Linux — установка с нуля (v6)

Инструкция воспроизводит рабочую конфигурацию на чистой Ubuntu 24.04
(подойдёт и для других Debian-подобных систем с поправкой на имена пакетов).
Результат: сканер работает через штатный SANE-backend `genesys` в сером и
цветном режиме на 75/100/150/200/300/600/1200 dpi, с выровненной по всей
ширине яркостью, в том числе из `simple-scan`, `xsane`, `gscan2pdf` и любых
других программ, использующих SANE.

Понадобится файл `opticbook4800-genesys-v6.patch`, чистый белый лист A4 и
около 30 минут.

Что даёт патч: сканер заведён в genesys отдельной моделью (OpticBook 3800 не
затронут); включена штатная калибровка затенения с эталоном белого по листу
на стекле; калибровка на каждом аппаратном шаге сенсора идёт в окне и режиме
считывания скана с тёмным проходом при выключенной лампе — так убираются
полосы от пыли в оптике, которые обычный трёхканальный проход не видит;
геометрия сведена по трём шагам сенсора; кэш калибровки; защита каретки от
движения назад и парковка до конца перед закрытием устройства; проверка
вменяемости калибровки (битая калибровка даёт ошибку, а не чёрные сканы).
Белая бумага выходит 187–198 из 255 в любом режиме, цветовой баланс на
белом 192/193/193.

v6 (сентябрь 2026) — патч перебазирован на текущий master SANE (1.4.0);
изменения против v5 перечислены в разделе 18.

---

## 0. Что нужно знать заранее

- Сканер должен быть подключён по USB и включён на всех шагах, где он
  упоминается. Между пробами его иногда полезно выключить и включить —
  это сбрасывает чип, если предыдущая программа завершилась нештатно.
- Все команды выполняются в терминале. Строки, начинающиеся с `sudo`,
  спросят пароль.
- Патч рассчитан на **текущую ветку master** sane-backends (на момент
  написания это версия 1.4.0) — её и берём. На релизный тег 1.2.1 патч
  тоже ложился, но в master с тех пор изменился код, вокруг которого мы
  правим, поэтому актуальна именно master-версия.
- Системный пакет `libsane1` остаётся установленным: наша сборка ставится
  в `/usr/local`, а в системный каталог подкладывается только один файл
  backend-а. Это самый безопасный путь; откат — одна команда.
- **Каретка этого сканера умеет ехать только вперёд.** Драйвер сам следит,
  чтобы калибровочный проход заканчивался раньше начала скана, и откажет с
  сообщением, если это не так (см. раздел 12). Не меняйте `y_offset` и
  положение калибровки в таблицах, если не понимаете, зачем.

## 1. Проверяем, что сканер виден системе

```bash
lsusb | grep -i 07b3
```

Ожидается строка вида:

```
Bus 001 Device 005: ID 07b3:1301 Plustek, Inc.
```

Если строки нет — проверьте кабель, питание, попробуйте другой порт USB.
Дальше идти нет смысла, пока `lsusb` сканер не показывает.

## 2. Устанавливаем инструменты сборки и зависимости

```bash
sudo apt update
sudo apt install -y git build-essential autoconf automake libtool \
    autoconf-archive gettext autopoint pkg-config \
    libusb-1.0-0-dev libxml2-dev libtiff-dev libpng-dev libjpeg-dev \
    sane-utils libsane1 libsane-common python3-numpy python3-pil
```

`sane-utils` даёт `scanimage` и `sane-find-scanner`; системные `libsane*`
нужны, чтобы `simple-scan` и прочие программы имели куда подключаться;
`python3-numpy` и `python3-pil` — для проверочных скриптов из пакета.

---

## 3. Забираем исходники SANE (ветка master)

```bash
cd ~
git clone https://gitlab.com/sane-project/backends.git sane-backends
cd ~/sane-backends
```

Клонируем целиком, без `--depth`: обрезанный клон не даст потом
перебазировать правки, если master уйдёт вперёд.

Проверка версии:

```bash
grep -m1 AC_INIT configure.ac
```

Выведет строку с текущей версией — на момент написания 1.4.0. Именно это
число будет в имени собранной библиотеки (`libsane-genesys.so.1.4.0`);
если у вас версия другая, подставляйте её везде, где ниже написано
`1.4.0`.

---

## 4. Накладываем патч

Скопируйте `opticbook4800-genesys-v6.patch` в домашний каталог, затем:

```bash
cd ~/sane-backends
git apply --check ~/opticbook4800-genesys-v6.patch && echo "патч ложится чисто"
git apply ~/opticbook4800-genesys-v6.patch
git status --short
```

`git status` должен показать четырнадцать изменённых файлов:

```
 M backend/genesys.conf.in
 M backend/genesys/enums.h
 M backend/genesys/genesys.cpp
 M backend/genesys/gl846.cpp
 M backend/genesys/image_pipeline.cpp
 M backend/genesys/image_pipeline.h
 M backend/genesys/low.cpp
 M backend/genesys/tables_frontend.cpp
 M backend/genesys/tables_gpo.cpp
 M backend/genesys/tables_memory_layout.cpp
 M backend/genesys/tables_model.cpp
 M backend/genesys/tables_motor.cpp
 M backend/genesys/tables_sensor.cpp
 M doc/descriptions/genesys.desc
```

Предупреждение `trailing whitespace` при наложении безвредно.

Если `git apply --check` ругается — значит master ушёл вперёд и задел
те же места, что и патч. Тогда накладывайте с трёхсторонним слиянием:

```bash
git apply --3way ~/opticbook4800-genesys-v6.patch
git status --short
```

Строки со статусом `UU` — файлы с конфликтом, их правят руками (маркеры
`<<<<<<<` / `>>>>>>>` в тексте). Если конфликтов нет, всё встало само.

## 5. Собираем только backend genesys

Полная сборка всех backend-ов SANE занимает долго и не нужна. Собираем
только `genesys` (и служебный `dll`, он добавляется сам):

```bash
cd ~/sane-backends
./autogen.sh
./configure --prefix=/usr/local BACKENDS="genesys"
make -j$(nproc)
```

Сборка занимает 2–5 минут. В конце ошибок быть не должно; предупреждения
компилятора (warning) — нормально.

Проверка, что библиотека собралась:

```bash
ls -l backend/.libs/libsane-genesys.so.*
```

---

## 6. Устанавливаем сборку в /usr/local

```bash
cd ~/sane-backends
sudo make install
sudo ldconfig
```

После этого появятся:

- `/usr/local/bin/scanimage` — наша версия утилиты;
- `/usr/local/lib/sane/libsane-genesys.so.1.4.0` — backend с поддержкой 4800
  (номер версии соответствует версии исходников);
- `/usr/local/etc/sane.d/` — конфигурация для нашей сборки.

---

## 7. Конфигурация SANE

### 7.1. Наша сборка (/usr/local)

Разрешаем backend-у genesys видеть сканер:

```bash
echo "usb 0x07b3 0x1301" | sudo tee -a /usr/local/etc/sane.d/genesys.conf
```

Убеждаемся, что в списке загружаемых backend-ов есть genesys:

```bash
grep -q "^genesys" /usr/local/etc/sane.d/dll.conf || echo "genesys" | sudo tee -a /usr/local/etc/sane.d/dll.conf
```

### 7.2. Системная конфигурация (/etc) — для simple-scan и остальных

```bash
echo "usb 0x07b3 0x1301" | sudo tee -a /etc/sane.d/genesys.conf
grep -q "^genesys" /etc/sane.d/dll.conf || echo "genesys" | sudo tee -a /etc/sane.d/dll.conf
```

---

## 8. Права доступа к USB-устройству

Создаём правило udev, чтобы сканер был доступен обычному пользователю:

```bash
sudo tee /etc/udev/rules.d/60-plustek-opticbook.rules > /dev/null <<'EOF'
ATTRS{idVendor}=="07b3", ATTRS{idProduct}=="1301", MODE="0664", GROUP="scanner", ENV{libsane_matched}="yes"
EOF
sudo udevadm control --reload-rules
```

Добавляем себя в группу `scanner` (она создаётся пакетом `libsane-common`;
если её нет — `sudo groupadd scanner`):

```bash
sudo usermod -aG scanner $USER
```

**Важно:** членство в группе вступает в силу после перелогина. Выйдите из
сеанса и войдите снова (или перезагрузитесь), затем проверьте:

```bash
groups | grep -q scanner && echo "группа scanner есть"
```

После этого выключите и включите сканер, чтобы udev применил правило.

## 9. Первая проверка — через нашу сборку

Эти команды используют библиотеку из `/usr/local` явно, независимо от
системной:

```bash
SANE_CONFIG_DIR=/usr/local/etc/sane.d LD_LIBRARY_PATH=/usr/local/lib \
  /usr/local/bin/scanimage -L
```

Ожидается:

```
device `genesys:libusb:001:005' is a PLUSTEK OpticBook 4800 flatbed scanner
```

OpticBook 4800 — отдельная модель в таблицах genesys; поддержка
OpticBook 3800 патчем не затрагивается.

Пробный скан 50×50 мм в сером:

```bash
SANE_CONFIG_DIR=/usr/local/etc/sane.d LD_LIBRARY_PATH=/usr/local/lib \
  /usr/local/bin/scanimage -d genesys --mode Gray --format=png --resolution 300 \
  -l 0 -t 0 -x 50 -y 50 > ~/test.png
```

При первом скане в каждом режиме (разрешение + серый/цвет) каретка делает
два коротких прохода по белой полосе под рамкой — тёмный с выключенной
лампой (каретка стоит) и белый, — возвращается на парковку и только потом
сканирует; результат калибровки сохраняется в
`~/.sane/plustek-opticbook-4800.cal`, и следующие сканы идут сразу.
В `~/test.png` — фрагмент того, что лежит на стекле. Если это так — backend
работает.

## 10. Эталон белого — один раз для каждого сканера

Без этого шага сканер тоже работает: яркость выравнивается по белой полосе,
которая спрятана под рамкой стекла. Но у этой полосы своя структура
освещения (у светодиодной лампы рябь по длине, и над плоскостью стекла она
выглядит иначе, чем на бумаге), поэтому на широких сканах остаются светлые
вертикальные полосы шириной в несколько мм и небольшой провал яркости в
середине листа. Лечится эталоном, снятым по белому листу прямо на стекле:
тогда эталон и оригинал лежат в одной плоскости и рябь вычитается точно.

Эталон привязан к конкретному экземпляру сканера (лампа, оптика). Он
нужен на каждый аппаратный шаг сенсора — 300 (обслуживает 75–300 dpi), 600
(200 и 600 dpi) и 1200 — и отдельно для серого и для цвета, потому что
калибровка идёт в режиме считывания скана, а серый и цвет читают линейку
по-разному. Итого шесть файлов.

Эталон задаёт только плавную часть освещения (рябь лампы); узкие детали —
пыль в оптике — драйвер берёт из своего калибровочного прохода перед
каждым сканом, поэтому ширина, с которой снят эталон, значения не имеет.

1. Положите на стекло чистый белый лист A4 **альбомно** (длинной стороной
   вдоль ширины стекла) — ровно, к левому и верхнему упорам, без текста и
   складок. Портретный лист оставляет ~3 мм справа без эталона, и любая
   бумага, попавшая туда, уходит в белое насыщение. Альбомный лист
   закрывает всё стекло по ширине, а по высоте с запасом накрывает зону
   40–44 мм от парковки, где идёт калибровочный проход.
2. Снимите шесть эталонов. Параметр `-t 20` **обязателен**: калибровочный
   проход при съёмке эталона идёт на 40–44 мм от парковки, а скан должен
   начинаться дальше него — каретка назад не ездит.

```bash
cd ~
for m in "Gray 300" "Gray 600" "Gray 1200" "Color 300" "Color 600" "Color 1200"; do set -- $m
rm -f ~/.sane/plustek-opticbook-4800.cal
OB4800_CALIB_Y_MM=40 OB4800_WHITE_REF_SAVE=1 \
SANE_CONFIG_DIR=/usr/local/etc/sane.d LD_LIBRARY_PATH=/usr/local/lib \
  /usr/local/bin/scanimage -d genesys --mode $1 --format=png --resolution $2 \
  -l 0 -t 20 -x 20 -y 5 > /dev/null && echo "$1 $2 ok"
done
ls -la ~/.sane/opticbook4800-white-*.dat
for f in ~/.sane/opticbook4800-white-*.dat; do echo -n "$f: "; head -c 32 "$f" | head -1; echo; done
```

Должны появиться шесть файлов: `opticbook4800-white-300-gray.dat`,
`-600-gray.dat`, `-1200-gray.dat` (серый) и `-300.dat`, `-600.dat`,
`-1200.dat` (цвет). Внутри — усреднённая белая строка, три канала, 16 бит,
без гаммы; заголовок `OB4800WREF2 <пикселей> 3 <старт окна>`.

3. Проверка по тому же листу (лист можно оставить как лежит):

```bash
rm -f ~/.sane/plustek-opticbook-4800.cal
SANE_CONFIG_DIR=/usr/local/etc/sane.d LD_LIBRARY_PATH=/usr/local/lib \
  /usr/local/bin/scanimage -d genesys --mode Gray --format=png --resolution 300 \
  -l 0 -t 0 -x 210 -y 10 > ~/white.png
python3 -c "
import numpy as np; from PIL import Image
a=np.asarray(Image.open('$HOME/white.png').convert('L')).astype(float)
c=a[30:100, 40:-40].mean(0); print('белое: медиана', int(np.median(c)), 'разброс', int(c.min()), '..', int(c.max()))"
```

Ожидается медиана ~190 и разброс по ширине не шире ~185..200. Тот же
контроль стоит повторить для 600 и 1200 в сером и в цвете (на 1200
достаточно `-y 10`). Если файла эталона для группы или режима нет, драйвер
калибруется по полосе под рамкой — работает, но с описанными выше полосами
от ряби лампы.

Эталон переснимают, если сканер разбирали, меняли лампу или сильно
загрязнилось стекло. Файлы лежат в домашнем каталоге того пользователя,
от которого запускается сканирование; для `simple-scan` это ваш обычный
пользователь, для сетевого `saned` — его пользователь.

## 11. Подключаем системные программы (simple-scan и другие)

Системные программы используют библиотеку из системного каталога, а не
из `/usr/local`. Подкладываем туда наш backend:

```bash
sudo cp /usr/local/lib/sane/libsane-genesys.so.1.4.0 \
        /usr/lib/x86_64-linux-gnu/sane/
sudo ln -sf libsane-genesys.so.1.4.0 \
        /usr/lib/x86_64-linux-gnu/sane/libsane-genesys.so.1
sudo ldconfig
```

Чтобы обновление пакетов не вернуло старый файл, замораживаем системные
пакеты SANE:

```bash
sudo apt-mark hold libsane1 libsane-common sane-utils
```

Проверка системным `scanimage`:

```bash
scanimage -L
```

Должна быть та же строка про Plustek OpticBook. Теперь запускайте
`simple-scan` («Сканер документов») — сканер будет в списке устройств,
режимы «Текст» и «Изображение» работают.

В simple-scan размер страницы задаётся в меню ≡ → «Параметры» → «Размер
страницы»: «A4» даёт ровно лист без рамы стекла, «Автоматически» — весь
кадр, 212 × 298 мм.

## 12. Примеры использования из командной строки

Полный лист A4, серый, 300 dpi (около 9 секунд; первый раз в режиме
на 5–6 секунд дольше из-за калибровки):

```bash
scanimage -d genesys --mode Gray --resolution 300 --format=png \
  -l 0 -t 0 -x 210 -y 297 > страница.png
```

Полный лист, цвет, 300 dpi:

```bash
scanimage -d genesys --mode Color --resolution 300 --format=png \
  -l 0 -t 0 -x 210 -y 297 > страница.png
```

600 dpi, серый (около 18 секунд, файл ~30 МБ):

```bash
scanimage -d genesys --mode Gray --resolution 600 --format=png \
  -l 0 -t 0 -x 210 -y 297 > страница600.png
```

Параметры: `-l`/`-t` — левый и верхний край области в мм, `-x`/`-y` —
ширина и высота в мм. Максимум: `-x 212 -y 298` — весь кадр (запрос
шире драйвер сам обрежет); лист A4 — `-x 210 -y 297`. Яркость и контраст после калибровки трогать
обычно не нужно; при желании `--contrast 25 --brightness -10`
(диапазон от −100 до 100).

Список всех параметров: `scanimage -d genesys --help`.

## 13. Если что-то не так

**`scanimage -L` ничего не находит.**
Проверьте по порядку: `lsusb` видит `07b3:1301`; строка `usb 0x07b3
0x1301` есть в `genesys.conf`; `genesys` есть в `dll.conf`; вы в группе
`scanner` и перелогинились; сканер выключали-включали после установки
правила udev.

**`open of device genesys failed: Invalid argument`.**
Сканер остался в занятом состоянии после предыдущей нештатно
завершённой программы, или его только что включили и он ещё не поднялся.
Выключите и включите сканер, подождите 10 секунд, повторите.

**`calibration area ... must end before the scan start ... (carriage cannot
move backwards)`.**
Защита каретки: калибровочный проход попросили сделать дальше начала
скана. Так бывает только при съёмке эталона (раздел 10) без `-t 20` или
при правке таблиц модели. Каретка при этом не двигалась — это и есть
смысл защиты. Исправьте параметры и повторите.

**Скан заканчивается ошибкой `shading calibration failed, the white
reference reads N`.**
Калибровочный проход снял мусор: лампа не успела зажечься, сканер не
проснулся, сбой USB. Драйвер отказал, чтобы не отдавать чёрные сканы и не
запоминать битую калибровку в кэше. Выключите и включите сканер, подождите
10 секунд, повторите.

**Скан выходит серым/тёмным по всей ширине или с широкими светлыми
полосами.**
Нет файлов эталона или они сняты не по белому листу. Пройдите раздел 10.
В логе (`SANE_DEBUG_GENESYS=4`) это видно как отсутствие строки `white
reference loaded` для нужного файла.

**Узкие вертикальные полосы (провал в 3–5 %, ширина доли миллиметра).**
Это пыль в оптическом тракте; драйвер убирает её калибровочным проходом
перед сканом. Если полосы всё же видны — сначала `rm -f
~/.sane/plustek-opticbook-4800.cal` и повторный скан (кэш мог быть снят до
того, как пыль сдвинулась); затем проверьте, что в логе есть строка
`shading window startx=... (channels ...)` — это признак калибровки в
окне скана.

**Скан 1200 dpi зависает и заканчивается `Error during device I/O`, дальше
сканер не отвечает.**
Выключите и включите сканер. Так ведёт себя чип, если калибровочный
проход попросили начать с нулевого пикселя сенсора на полном такте или
дали экспозицию не той группы; драйвер v6 обе ситуации исключает. Если
повторяется — проверьте, что установлена именно эта сборка (в `gl846.cpp`
есть строка `shading window startx`), и снимите лог с `SANE_DEBUG_GENESYS=4`.

**Чёрное не чёрное: плотная заливка выходит ~35/255.**
Это не ошибка. Тёмный уровень измеряется при выключенной лампе и
вычитается ровно столько, сколько есть; остаток — реальный свет (отражение
тонера плюс засветка запылённого тракта). Если нужен чёрный в ноль — это
регулировка чёрной точки в программе сканирования (яркость/контраст), не
калибровки.

**Каретка издаёт хруст.**
Немедленно выключите питание. Хруст — это упор в конце хода; для механики
не смертельно, но повторять не надо. Причины две: каретку
попросили ехать назад (калибровка дальше скана, или `y_offset` меньше
конца калибровки), либо новая команда движения пришла, пока каретка ещё
ехала домой после предыдущего скана. Драйвер v6 отсекает обе: калибровку
дальше скана отвергает с сообщением, а устройство не отпускает, пока
каретка не припаркована. Если хруст случился — проверьте, что установлена
именно эта сборка (в `genesys.cpp` есть строка `Never leave the carriage
moving`). Тёмный проход каретку не двигает вовсе (мотор для него не
запускается).

**Сканер найден, но скан зависает.**
Выключите и включите сканер. Если повторяется — снимите лог и смотрите
последние строки:

```bash
SANE_DEBUG_GENESYS=5 scanimage -d genesys --mode Gray --resolution 300 \
  -x 50 -y 50 > /dev/null 2> ~/genesys.log
tail -50 ~/genesys.log
```

**После обновления системы сканер пропал в simple-scan, но работает
через /usr/local.**
Системный пакет перезаписал backend. Повторите раздел 11.

**Перед сканом каретка делает лишний короткий проход и возвращается.**
Это калибровка затенения при первом скане в режиме (разрешение + цвет/серый),
5–6 секунд (тёмный и белый проходы); результат кэшируется в `~/.sane/plustek-opticbook-4800.cal`, и
дальше сканы идут сразу. Если проход повторяется каждый раз — кэш не
записывается (нет прав на `~/.sane/`) или сканирует другой пользователь.

**После пересборки драйвера или пересъёма эталона.**
Удалите кэш, иначе поднимется старая калибровка:
`rm -f ~/.sane/plustek-opticbook-4800.cal`.

## 15. Служебные переменные окружения

Драйвер понимает несколько переменных, нужных для съёмки эталона и
отладки. В обычной работе не задаются.

| Переменная | Назначение |
|---|---|
| `OB4800_CALIB_Y_MM=<мм>` | разово перенести калибровочный проход (18–60 мм от парковки); используется при съёмке эталона вместе с `-t`, чтобы скан начинался дальше |
| `OB4800_WHITE_REF_SAVE=1` | сохранить снятую калибровкой белую строку как эталон группы и режима (шесть файлов, см. раздел 10) |
| `OB4800_SHADING_TARGET=0x....` | переопределить целевой уровень белого (по умолчанию 0xa400 для всех шагов; белая бумага ~187–198) |
| `OB4800_CALIB_LEGACY=1` | калибровать в окне скана только на 1200 dpi, как в v5 (на 300/600 вернётся старый трёхканальный проход с нуля; сравнение) |
| `OB4800_CALIB_3CH=1` | серый калибровать трёхканальным проходом (сравнение до/после; полосы вернутся) |
| `OB4800_NO_DARK_PASS=1` | не делать тёмный проход с выключенной лампой (тёмный уровень возьмётся по закрытым пикселям CCD) |
| `OB4800_WREF_NODARK=1` | не перебазировать эталон на тёмный уровень текущего прохода (сравнение; вернётся светлая зона слева) |
| `OB4800_WREF_REPLACE=1` | применять эталон подменой строки, как в v5, а не плавным множителем (сравнение; вернутся полосы от пыли) |
| `OB4800_SHADING_SHIFT=<px>` | сдвинуть таблицу затенения относительно окна (по умолчанию 0, выверено по соринке на стекле) |
| `OB4800_SHADING_TEST=1` | вместо коэффициентов залить единичную таблицу с тестовыми полосками (×0.5/×1.5/×2/×4/×6 на записях 500–760) — даёт сырой уровень сенсора |
| `OB4800_AFE_OFS_DELTA=<n>` | прибавка к кодам усиления АЦП (регистры 2–4) |
| `OB4800_AFE_GAIN_DELTA=<n>` | прибавка к регистрам АЦП 5–7 (смещения; на яркость почти не влияет) |
| `SANE_DEBUG_GENESYS_IMAGE=1` | штатный дамп genesys: калибровочные проходы и промежуточные картинки конвейера в текущий каталог (tiff) |

### 15.1. Отладочная печать таблицы затенения

В логе на уровне 5 драйвер печатает, что легло в таблицу для пикселя 1000
(канал G): усреднённое белое и тёмное, цель, коэффициент и готовую запись
dark/gain. По ней сразу видно, из чего посчитан коэффициент, — так были
найдены ошибка с кэшем и ошибка экспозиции после переезда на master.

```bash
rm -f ~/.sane/plustek-opticbook-4800.cal
SANE_DEBUG_GENESYS=5 SANE_CONFIG_DIR=/usr/local/etc/sane.d LD_LIBRARY_PATH=/usr/local/lib \
  /usr/local/bin/scanimage -d genesys --mode Gray --format=png --resolution 300 \
  -l 0 -t 0 -x 120 -y 50 > /dev/null 2> ~/dbg.log
grep -o "OB4800 px1000.*" ~/dbg.log
```

Пример нормальной строки для группы 300:
`white=59110 dark=514 target=0xa400 coeff=0x2000 -> record dark=514 gain=5869`.
Тёмное ~500 (пьедестал при выключенной лампе) — норма; тёмное в десятки
тысяч или белое в 65535 — признак сломанной калибровки.

## 16. Что поддерживается

| Режим | 75 | 100 | 150 | 200 | 300 | 600 | 1200 |
|-------|----|-----|-----|-----|-----|-----|------|
| Серый | ✓  | ✓   | ✓   | ✓   | ✓   | ✓   | ✓ |
| Цвет  | ✓  | ✓   | ✓   | ✓   | ✓   | ✓   | ✓ |

Все режимы проверены на бумаге; серый 1200 — на полном листе A4 (файл
140 МБ, около 70 секунд). На 1200 dpi мотор идёт медленно и гудит громче
обычного — это нормально для шагового двигателя на низких оборотах.

Аппаратных шагов у сенсора три — 300, 600 и 1200 dpi; 75, 100, 150
снимаются на 300 и уменьшаются программно, 200 — на 600 (поэтому по времени
как 600). Список в simple-scan (75/150/200/300/600/1200/2400) совпадает с
поддерживаемым, кроме 2400: его драйвер подменяет на 1200, а simple-scan
растягивает картинку вдвое — детализации это не добавляет.

Область сканирования: 212.0 × 298 мм — линейка сенсора без последних
33 пикселей (окно до самого конца линейки чип отдаёт со сдвигом). Стекло
справа шире ещё на ~6 мм, но сенсора под ними нет — эту зону не сканирует
ни один драйвер. Начало кадра стоит на 0.5 мм внутри
края листа, чтобы при листе у упора в кадр не попадала рама; из-за этого
запрос ровно A4 (210 мм) захватывает 0.5 мм за правым краем листа —
там подложка крышки, тёмная полоска шириной в несколько пикселей. Это не
дефект, а то, что реально лежит на стекле: драйвер отдаёт кадр как есть и
ничего не дорисовывает. В simple-scan размер страницы выбирается только
из списка (A4, Letter, «Автоматический» и т. д.; «Автоматический» — это
весь кадр, 212 мм, с ~2 мм подложки справа). Если нужен кадр строго
внутри листа, ширину задают числом: `scanimage -x 208.6`, xsane, gscan2pdf.
Родной драйвер Windows режет так же (его A4 — 210.2 мм от того же начала
кадра). Масштаб выверен по банковской карте
(85.60 мм по стандарту): у сенсора шаг на 0.4 % крупнее номинала по обеим
осям, драйвер это компенсирует программно; начало кадра у трёх аппаратных
шагов сенсора разное (600 на 0.95 мм и 1200 ещё на 0.47 мм правее 300),
это тоже сведено — карта на 300/600/1200 лежит в одном месте с точностью
0.2 мм. Скорость: A4 серый 300 dpi ≈ 9 с, цвет 300 dpi ≈ 11 с, серый
600 dpi ≈ 18 с; первый скан в режиме на 5–8 с дольше (тёмный и белый
калибровочные проходы).

Яркость: калибровка затенения включена, белая бумага выходит ~187–198 из
255 во всех режимах (одна цель 0xa400 на все шаги сенсора, серый и цвет),
разброс по ширине листа единицы процентов, цветовой баланс на белом
192/193/193. Усиление АЦП для 600 и 1200 dpi снижено относительно значений
родного драйвера — иначе белая бумага упиралась в потолок. На другом
экземпляре сканера уровень может немного отличаться; тогда сначала
пересъём эталонов (раздел 10), а если мало — `OB4800_SHADING_TARGET`
(например, 0xc000 даст белое около 225, но оставит меньше запаса до 255).
Чёрная точка — см. раздел 13.

## 17. Оцифровка книг: рабочий процесс

Сканер книжный, и после установки драйвера обычно нужен путь до готового
PDF: ровные страницы одного размера, без пыли, с текстовым слоем и
оглавлением. Проверенная схема на Ubuntu — три шага, ручной работы в них
почти нет.

**Шаг 1. Сканирование — серый, 300 dpi, PNG, вся область.**
Не simple-scan: у него нет ширины числом и серийной съёмки. Подходят
`gscan2pdf` (в репозитории Ubuntu: область числом, серии страниц,
автонумерация, PNG) или `xsane`. Либо из терминала, страница за страницей:

```bash
mkdir -p ~/book && cd ~/book
n=1; while true; do
  read -p "страница $n: положите разворот и нажмите Enter (q — конец) " a; [ "$a" = q ] && break
  scanimage -d genesys --mode Gray --resolution 300 -l 0 -t 0 -x 212 -y 297 --format=png > $(printf "p%04d.png" $n)
  n=$((n+1))
done
```

Область берите всю (212 мм) — обрезка будет на шаге 2. Для мелкого
шрифта и сносок сканируйте 600 dpi и уменьшайте потом: бинаризация из 600
заметно чище. Разворот кладите корешком к краю стекла, как задумано у
книжного сканера.

**Шаг 2. Чистка и единый размер — ScanTailor Advanced.**
Стандартный инструмент для книг (Flathub: `com.github._4lex4.ScanTailor-Advanced`,
Snap: `scantailor-advanced`). Работает по стадиям: поворот → разрезание
разворота на две страницы → выравнивание перекоса → выбор области
содержимого (подложка за краем листа и рамка уходят здесь) → поля с
**единым размером всех страниц** (содержимое выравнивается, размер в PDF не
прыгает) → вывод. На выводе: режим «смешанный» (текст бинаризуется,
иллюстрации остаются серыми), удаление мусора (despeckle) снимает пыль и
точки пакетно, есть выпрямление изгиба у корешка. Результат — TIFF/PNG
300 dpi одного размера для всех страниц.

**Шаг 3. PDF, OCR, оглавление.**
На Ubuntu: `ocrmypdf` (пакет `ocrmypdf`, язык `tesseract-ocr-rus`) —
PDF/A с текстовым слоем и сжатием одной командой:

```bash
img2pdf out/*.tif -o book_raw.pdf && ocrmypdf -l rus --optimize 3 book_raw.pdf book.pdf
```

На Windows: Adobe Acrobat Pro («Улучшить сканы» → «Распознать текст») или
ABBYY FineReader — для русских книг он точнее. Оглавление ни один из них
из сканов не строит; практичный путь — распознать страницу с содержанием
книги, получить список «глава — номер страницы» и загрузить его как
закладки в JPDFBookmarks (есть смещение номеров страниц, работает на
Linux и в командной строке). Для полностью автоматического оглавления
без страницы содержания есть нейросетевые разборщики структуры (MinerU,
Marker, Docling): выдают текст с уровнями заголовков, из которых
скриптом собирается список закладок; требуют настройки и желательно
видеокарты — для одной-двух книг ручной путь быстрее.

Нейросетевые «улучшатели» изображений для чистки сканов с планшетника
не нужны: пыль и точки — задача морфологии, ScanTailor решает её
предсказуемо, а нейросеть может дорисовать то, чего в книге не было.

## 18. Что изменилось в v6 (против v5)

- Патч перебазирован на master SANE (1.4.0). В master экспозиция строки
  берётся из опции `--scan-exposure-time`, которая для этого сканера не
  подходит (экспозиция привязана к такту CCD и профилю мотора) — теперь
  драйвер берёт её из профиля сенсора всегда, опция игнорируется.
- Калибровка в окне и режиме считывания скана с тёмным проходом — на всех
  шагах сенсора, не только на 1200. Эталонов стало шесть (серые и цветные на
  каждый шаг), ширина съёмки не важна.
- Эталон применяется как плавный множитель к живому калибровочному проходу
  (раньше подменял его целиком): пыль всегда берётся из прохода, рябь
  лампы — из эталона.
- Исправлено смещение чтения таблицы затенения на 300/600 (копия каждого
  провала от пыли стояла на несколько мм правее).
- Кадр по ширине 212.0 мм (было 212.7).
- Битая калибровка (белое ниже пятой части цели) даёт ошибку с текстом и не
  попадает в кэш.
- Каретка всегда паркуется до конца перед тем, как драйвер отпускает
  устройство; сканы подряд без пауз безопасны.
- Отладочная печать таблицы (`OB4800 px1000`) оставлена в драйвере на
  уровне 5.
